# personal-web content integration

Apply these instructions only in the existing personal-web repository. Resolve the following paths from its root, not from an unrelated working directory.

- Read `AGENTS.md`, `DESIGN.md` and `docs/content-voice.fa.md` for current author choices and review boundaries. Use the established anti-slop mode; do not ask again when the session already selected it. Finalize reviewed Persian meaning before writing native English.
- For interactive articles use this method alongside `.agents/skills/interactive-blog-anatomy/SKILL.md`, `docs/interactive-blog.md` and `prompts/interactive-blog.fa.md`. Anatomy is optional. Read `.agents/skills/interactive-data-visuals/SKILL.md` for suitable categorical, dated, geographic or scheduled data, and `MOTION.md` for an actual data-motion decision. No figure is mandatory.
- Use the shared article engine, sidebar, reading progress, source ledger, related links and AbortSignal lifecycle. The article's reader question determines supported interactions; a new block must have meaningful behavior and corresponding validation. Do not copy the full renderer for a post.
- Keep the source object's identity, category, evidence type, input/output, dependencies, unit, date precision and unknowns where applicable. Distinguish reported data from editorial proposals and training examples. Do not add dated or numeric detail solely to fit a visual.
- When covers are in scope, create separate native fa/en WebP assets with the coordinated title, related artwork and restrained keywords. Follow the next open `bannerPair` in `AGENTS.md`; do not hard-code a pair or palette in this skill. Inspect both images for text, composition, identifiable product marks and anatomy. A useful in-body image needs native alt and caption. Record actual prompts and provenance in the existing cover documentation.
- `posts/ai-content-system.mjs` is a worked integration using tabs, a categorical workflow, an educational comparison and a local prompt starter. `blog-content-model.mjs` and `blog-content-studio.mjs` do not call an AI service, connect accounts or publish. Use them only when preparing a prompt/starter answers the current article's question; they are not mandatory blocks.
- Run `node scripts/check-blog-skills.mjs` for authoring-skill changes. For actual article/runtime changes, follow the existing syntax/model, scoped site test, native-language and permitted browser checks. Regenerate/check the sitemap when publication changes. Do not add UI tests or redeploy the site for instruction-only changes.
- Follow the session's Git/publication authorization. Keep account details, private user notes, raw customer records, personal device paths and internal evaluations out of public source and documentation. A source file excluded from the UI can still be public in Git.

For the original guide's evidence boundaries and product documentation links, consult `docs/ai-content-system.md` when relevant. Recheck current primary sources before giving product-specific setup or pricing; do not freeze a dated UI instruction as a universal requirement.
