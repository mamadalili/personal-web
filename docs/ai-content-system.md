## Reader tool and evidence objects

`content-studio` keeps a native tool selector, post objective, audience and working note beside a reviewable prompt. Tool selection changes access guidance; the goal changes the requested reader action. Copy has an explicit fallback; Markdown download carries editable sections for `brief.md`, `evidence.md`, `voice.md`, `drafts.md`, `review.md` and `results.csv`. Inputs remain in the page until copied or downloaded; there is no model request, account connection, storage, telemetry or publication.

The pure model validates language, tool, goal, trimmed lengths and maximum input lengths. User text is displayed through textarea values, and Markdown uses a literal fence longer than any supplied backtick run. Async clipboard completion checks abort, connection and output identity. Listeners and download URLs are disposed on remount. Tests cover route semantics, different objectives, native literal text, invalid input and robust exported fences.

The workflow is an editorial proposal: record a question, inspect evidence, write a brief, draft, review and inspect the outcome after manual publication. These are categorical dependencies with review criteria, not a time estimate or measured automation rate. No Gantt, calendar, map or physical Anatomy figure is needed.
