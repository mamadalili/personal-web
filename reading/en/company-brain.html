Why does the same question keep coming back?

Last week, a colleague asked AI about returns and received a useful answer. Today, someone else asks again. The policy sits in a folder, its change was discussed in chat, and the person who knows why is in a meeting. Finding a file is only part of the problem. We need to establish which answer is valid now.

A “company brain” is a grand name for a familiar need: what the team knows should remain usable after a meeting ends or a chat closes. The next person should be able to find it, understand the reason and judge whether it applies today. AI agents make the need more visible because they also depend on clear information to do useful work.

The three supplied sources approach the problem through small-team setups, Cerebras’s technical experience and a distinction between scattered information and shared context. We will use an actual question, a few inspectable documents, an owner and a way to check the answer before choosing more tooling.

Separate the file, the claim, the decision and access

Imagine a message saying that an item can simply be sent back. The message is evidence, but we do not yet know whether it is a question, suggestion or approved policy. If the support owner later adds a condition, keeping the two texts is insufficient. We also need their relationship: who said what, which decision was confirmed and when it took effect.

Keep four things distinct. Evidence is the original document or conversation. A claim is what it appears to establish. Judgment checks which claim applies to the question. Access determines what the person asking may use at all. A fluent answer is not a substitute for any of them.

Ask the same question through different roles and times

The fictional shop has changed its returns policy. The earlier version allowed returns without prior arrangement; the approved revision requires support coordination. A newer chat message still assumes the earlier rule applies. Change the point in time below and see why the latest text is not automatically the best answer source.

One question, three roles and three points in time

Change the role and point in the example. Inspect the answer’s source, then open it to see its date and owner.

Now change the role. The external collaborator can see only public guidance; an internal finance note or inaccessible policy should not supply their answer. Finance can see more, but the extra document may not answer this particular question. Permission to read and relevance to the question are separate checks.

If two approved rules conflict at the same time, a reliable response should expose the disagreement rather than silently select one. Someone must own its resolution. Sometimes the right response is that the evidence does not yet support an answer. That is preferable to turning a guess into the team’s routine decision.

You may already have enough tooling to start

The first source’s useful starting point is to inspect what you already have before buying another subscription. A shared project, document folder or connected search tool may support the first use case. That depends on knowing what has been added, who can see it and who keeps it current.

We should not read the reference graphics as proving that AI answers must remain trapped in private chats. Current ChatGPT documentation describes shared projects and saving a response as a project source. The more useful questions are whether the team actually does that, reviews the saved material and provides suitable access for other tools. Product features and working practices both matter.

Sharing a folder with everyone is not the same as preserving each source file’s permissions. Nor does one connection automatically give every agent access. Test the actual account and environment that will be used. A plan name or “connects to your data” claim is not enough.

Five approaches, chosen around the actual bottleneck

Kevin Simback arranges five approaches from simpler to more technical. That is not a quality ranking. A maintained folder may suit one use case while another needs more integration and controls. For each option, ask who keeps the information current and which responsibilities remain with the team.

Shared documents

Start with a limited, maintained collection

Use a defined collection of shareable guidance and decisions alongside an existing AI project. It can support a first shared question if someone maintains it. Material outside the collection, unrecorded changes and other agents’ access remain separate concerns. There is no need to move the entire company into one folder.

Text files and a connection

Portable text with reviewable changes

Keep knowledge in versioned text files and expose suitable access through a mechanism such as MCP. Text can be inspected and moved. Agent identity, read/write permissions, change review and backups still need to be designed. Markdown files alone do not provide those controls.

Self-hosted workspace

Chat, documents and synchronisation on your infrastructure

Connect a chat environment to documents and update flows. The author mentions Open WebUI and AnythingLLM as examples. You control more components, but also own broken integrations, software updates and recovery. Hosting it yourself does not make maintenance free or permissions correct.

Connected search

Search reaches the tools where work remains

Instead of manually copying everything, a search layer connects to existing sources. Onyx is one example in the source. Check what each connector ingests, how edits and deletions propagate and which permissions the chosen edition supports. A connector or cited result alone does not prove those behaviours.

Custom memory

Retain relationships between decisions and changes

Understanding who changed a decision and why may require relationships between people, claims and validity periods. Memory or graph tools can be components, but a graph does not establish truth by itself. This path needs data design, conflict review and technical maintenance; it is not every small team’s default starting point.

A more complex product will not supply an absent owner. A simpler setup must not solve sensitive access by making everything visible to everyone. Start with those constraints, then compare costs, integrations and features. The source’s prices and setup times are its estimates, not an implementation budget for this article.

What to learn from Cerebras without copying its scale

Cerebras reported in July 2026 that employees asked its internal knowledge base more than 15,000 questions a day. The tool is also used by agents and automations. That is the company’s usage report, not evidence of financial returns for your team. The transferable lesson concerns how information is handled.

Its system collects information where work happens and combines complementary search methods. Exact matching helps with a literal term or error; semantic matching links differently worded questions and answers. Results are then reviewed for relevance and expanded with surrounding context.

For a small team, preserve the conversation needed to interpret a message and do not equate shared vocabulary with a correct answer. “Yes, go ahead” establishes little without the earlier question. Test that problem on routine team answers before trying to replicate Cerebras’s infrastructure.

Record one decision so the next person need not guess

You do not need to ingest every message to begin. In the shop example, write one decision note: the returns rule, which products or orders it covers, when it takes effect, who confirmed it, where the original evidence lives and who may read it. Include the reason for the change so the next colleague does not inherit an unexplained instruction.

If an AI answer adds a useful observation, do not silently turn it into company policy. Let the owner review the proposed text, then record the approved revision and its evidence. An agent can help draft an update; proposing a change and authorising its publication are different permissions.

When a source changes or is deleted, its summaries need a defined treatment too. Someone may lose access to an original while a copied summary remains in a shared project. Inspect the copies, summaries and final outputs as well as the original folder’s permissions.

When does the company-brain label become useful?

The following test comes from the first author’s proposed definition. It is not an official standard or security certification. A simple folder may meet today’s need without passing it. Its value is to put the product label aside and inspect actual behaviour.

Three foundations, plus at least one additional capability

This is Kevin Simback’s proposed test. Mark only what you have checked with a real question and a test account, rather than a feature name on a sales page.

If you need search and answers, test that job. If several agents need to read and write, test each agent’s connection and authority separately. MCP can provide a connection mechanism; it does not itself establish valid versions, approve edits or grant information access.

First, make one answer work from end to end

Start with questions already being repeated: what is the returns rule, why was a discount approved, which guide is current, who owns a product, or what changed after the last meeting? You do not have to solve all of them together. Choose one with available evidence and an identifiable decision owner.

Try the question through an ordinary colleague, a restricted account and an older version. Inspect the cited evidence, what the answer cannot establish and how conflicts are handled. Once that route works, consider the next integration or tool. Headcount alone does not decide: sensitivity, fragmentation and maintenance capacity matter too.

A useful first result lets the next person identify the answer’s evidence and the owner who can correct it. If the work still depends on one person’s memory or a chat history, make that decision maintainable before buying more tooling. Continue with putting enterprise data to work or defining AI agents’ authority.
